# YALLA KIDS: מה להדביק ואיפה (סליקה ב-Grow + וואטסאפ)

כל הקוד כבר מוכן ונבדק. נשאר רק לפתוח חשבונות ולהדביק מפתחות בקובץ ההגדרות בשרת
(`/etc/yalla-api.env`). **מפתחות לא שולחים בצ'אט.** מדביקים אותם רק בשרת.

אחרי כל הדבקה מפעילים מחדש ובודקים:

```
sudo systemctl restart yalla-api
cd /opt/yalla-api/server && sudo -u yalla-api bash -c 'set -a; . /etc/yalla-api.env; node admin.mjs selfcheck ping'
```

הבדיקה מראה מה מוגדר, מה חסר ואיפה יש בעיה. היא לא מדפיסה אף סוד.

---

## חלק א: וואטסאפ (חינם)

**מה צריך:** מספר טלפון ייעודי לעסק. הוא לא יכול להיות מספר שכבר פעיל באפליקציית וואטסאפ רגילה.

1. **חשבון עסקי ב-Meta.** נכנסים ל-business.facebook.com ופותחים Business Portfolio על שם העסק.
2. **אפליקציה.** ב-developers.facebook.com בוחרים Create App, סוג Business, ומוסיפים את המוצר **WhatsApp**.
3. **מספר.** ב-WhatsApp, תחת API Setup, מוסיפים את מספר העסק ומאמתים אותו בקוד SMS או בשיחה.
4. **Webhook.** ב-WhatsApp, תחת Configuration:
   - ב-Callback URL כותבים `https://<הכתובת של האתר>/api/whatsapp/webhook`
     (הכתובת המדויקת מופיעה בבדיקה העצמית, בשדה `callbackUrl`).
   - ב-Verify token מדביקים את הערך של `WA_VERIFY_TOKEN` מהקובץ. זו מחרוזת אקראית שאתם ממציאים:
     `openssl rand -hex 24`.
   - לוחצים Verify and save, ואחר כך מסמנים Subscribe ליד השדה **messages**.
5. **מה להדביק בשרת:**

| שורה בקובץ | מאיפה לוקחים |
|---|---|
| `WA_NUMBER` | מספר העסק בספרות בלבד, למשל `9723XXXXXXX` |
| `WA_APP_SECRET` | App settings ← Basic ← App secret |
| `WA_VERIFY_TOKEN` | אותה מחרוזת שהדבקתם ב-Meta בשלב 4 |
| `WA_TOKEN` | רשות. Business settings ← System users ← Generate token, עם ההרשאות `whatsapp_business_messaging` ו-`whatsapp_business_management`. בלעדיו לא נשלחת לאבא או לאמא ההודעה "מחוברים ✅", אבל הכניסה עובדת. |
| `WA_PHONE_NUMBER_ID` | רשות, ביחד עם `WA_TOKEN`. API Setup ← Phone number ID |

6. **בדיקה:** מריצים `selfcheck ping`. בשדה `whatsapp.ping` צריך להופיע שם העסק. אחר כך נכנסים לעמוד ההורים
   ולוחצים "כניסה עם וואטסאפ".
7. **לפני שמשפחות אמיתיות נכנסות:** מעבירים את האפליקציה ב-Meta למצב Live.

**עלות:** הודעה שהורה שולח לעסק היא חינם, ותשובה בתוך 24 שעות גם היא חינם. אנחנו אף פעם לא שולחים הודעה ראשונה.
כדאי לוודא את המחירון של Meta ביום ההקמה.

## חלק ב: סליקה ב-Grow (לשעבר משולם)

**הסליקה כבויה עד שתגידו "יוצאים לדרך".** אפשר להדביק הכול מראש ולבדוק בסביבת ניסיון. אין כסף אמיתי עד
שמשנים שתי שורות בסוף.

1. **פתיחת חשבון.** פונים ל-Grow (grow.business) ומבקשים חשבון סליקה לעסק, עם גישת API ("Light server").
   מבקשים הצעת מחיר בכתב לפני שחותמים. **שום תשלום לא יוצא בלי אישור שלכם.**
2. **שני דפי תשלום.** מבקשים מ-Grow, או פותחים בעצמכם בממשק:
   - דף **הוראת קבע** (חיוב חודשי), בשביל המסלול החודשי (39 ₪);
   - דף **תשלום רגיל** (חד-פעמי), בשביל המסלול השנתי (349 ₪). השנתי הוא תשלום אחד בלי חידוש אוטומטי.
   - בשני הדפים מפעילים חשבונית אוטומטית. אם רוצים, מפעילים גם Bit, Apple Pay ו-Google Pay.
3. **מה להדביק בשרת:**

| שורה בקובץ | מאיפה לוקחים |
|---|---|
| `GROW_USER_ID` | Grow נותנים, יחד עם גישת ה-API |
| `GROW_PAGE_CODE_RECURRING` | ה-pageCode של דף הוראת הקבע |
| `GROW_PAGE_CODE_ONETIME` | ה-pageCode של הדף החד-פעמי |
| `GROW_WEBHOOK_KEY` | מחרוזת אקראית שלנו: `openssl rand -hex 24`. לא נותנים אותה לאף אחד. השרת מצרף אותה לבד בכל תשלום. |
| `GROW_SANDBOX` | משאירים `1` (סביבת ניסיון) |
| `BILLING_PROVIDER` | `grow` |

   ב-Grow לא צריך להדביק כתובת. השרת שולח להם את כתובת העדכון בכל תשלום.
4. **בדיקה בסביבת ניסיון.** כדי לבדוק, מפעילים זמנית `BILLING_ENABLED=1`, כשהשורה `GROW_SANDBOX=1` עדיין בקובץ.
   - עושים מנוי חודשי עם כרטיס בדיקה של Grow, ובודקים שהמנוי נהיה פעיל.
   - מבטלים מעמוד ההורים, ובודקים ב-Grow שהוראת הקבע נעצרה.
   - עושים גם מנוי שנתי אחד.
   - בסוף מחזירים `BILLING_ENABLED=0`.
5. **השקה בתשלום (רק אחרי הפיילוט, ורק באישור שלכם):** עורך דין עובר על התנאים ועל מדיניות הפרטיות. אחרי
   זה משנים בקובץ `GROW_SANDBOX=0` ו-`BILLING_ENABLED=1`, ומריצים בדיקה עצמית.

**אבטחה:** פרטי האשראי לא מגיעים אלינו בכלל, כי ההורה משלם בדף של Grow. Grow לא חותמים על העדכונים שהם
שולחים, ולכן כל עדכון צריך לעבור שלוש בדיקות:
- המפתח הסודי בכתובת;
- התאמה לתשלום שאנחנו פתחנו;
- אישור חוזר מול Grow.

## חלק ג: SMS (גיבוי למי שאין וואטסאפ)

כרגע השרת לא שולח SMS (`SMS_PROVIDER=mock`). כשתבחרו ספק ישראלי, למשל InforU או 019, אני מחבר אותו. החיבור
הוא קובץ אחד. עד אז הכניסה היא בוואטסאפ.

## אזהרות שהבדיקה העצמית תציג אם משהו לא בסדר
- `MOCK_PAY=1` או `SMS_DEV_ECHO=1` בשרת החי. אסור, אלה מיועדים לבדיקות בלבד.
- `PUBLIC_URL` לא מתחיל ב-`https://`.
- הסליקה פתוחה אבל חסרים מפתחות של Grow.
